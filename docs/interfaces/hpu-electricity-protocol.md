# 河南理工 宿舍电费 接口协议（北校区，已破解）

> **2026-11-20 补充南校区**：`http://183.169.***.***:8080/Default.aspx`，与本协议**完全同款**
> （WebForms `__VIEWSTATE` 三级回发 + `__EVENTTARGET` + `radio=usedR` + 302→`/usedRecord.aspx` +
> `ASP.NET_SessionId` cookie + GB2312），只是楼栋字典不同（松园/竹园/梅园/兰园/利莫瑞克，
> 空调另编 31~45）。结果页同时含「备用剩余电量：0.00 度」和「竹园1#101照明剩余电量：XXX.XX 度」
> —— 房间名带中文前缀与照明/空调后缀，**解析正则必须能匹配**，且要取带 `#` 的房间那条。
> App 已用 `SchoolConfig.URL_SDCX`（北）/`URL_SDCX_SOUTH`（南）两套 client 实现。
> 实测：南 竹园1#101照明=XXX.XX 度、北 7#201=XXX.XX 度。
>
> **2026-11-20 二次踩坑与修正（重要）**：
> 1. **同一站点不同页面编码不同**：`Default.aspx`（三级联动表单页）是 **GB2312**，
>    `usedRecord.aspx`（结果页）是 **UTF-8**。客户端写死 GB2312 会让结果页整页乱码，
>    表现为「楼栋楼层都正常、就是查不到电量」（真机日志 `balance not found in result page`）。
>    修法：逐响应嗅探——严格 UTF-8 试解，失败才回退 GB2312。
> 2. **空调表计房间名带短横线**：照明 `竹园1#101` / 空调 `竹园1#-101`，正则要写成 `#-?[0-9]+`。
> 3. **照明与空调是站上两个独立楼栋编号**，VIEWSTATE 与楼栋绑定（借用照明页的 VIEWSTATE
>    查空调返回空），所以两个表计各自要走一次「楼栋→楼层」回发。编号规则是
>    `楼栋(2位)+楼层(2位)+房间(2位)`，换表计只需换前两位：
>    南 `09/0901/090101 ↔ 41/4101/410101`、`01 ↔ 51`；北 `07/0702/070201 ↔ 27/2702/270201`。
>    实测一条房间可同时查到照明与空调两个读数（南竹园1#101 = XXX.XX / XX.XX；
>    北7#201 = XXX.XX / XX.XX；北7#110淋浴间只有照明、空调表计无此房间）。
> 4. 北校区两套命名不一致：照明 `1号公寓照明`、空调 `1号楼空调`，合并成「一栋楼」时
>    归一化要把 `号公寓` 折成 `号楼`。
> ⚠️ **南校区是裸 IP + 明文 HTTP**，`network_security_config.xml` 必须单独放行
> `<domain includeSubdomains="false">183.169.***.***</domain>`，否则真机报
> `CLEARTEXT communication to 183.169.***.*** not permitted by network security policy`
> （2026-11-20 真机日志实证）。只放行 `hpu.edu.cn` 不够——裸 IP 不属于该域。

> 状态：**协议已拿到**（2026-11-19 抓包 `sdcx.hpu.edu.cn.har`，70 条）。
> 站点是 **ASP.NET WebForms**（`.aspx` + `__VIEWSTATE` 回发），不是 REST。

## 1. 关键结论

1. **无需登录**：所有请求不带 CASTGC / UIA 会话，直接 POST 即可查——实现时**不用复用 `HpuSessionStore`**，也无需验证码。
2. **三级联动**：楼栋 → 楼层 → 房间，靠 WebForms 回发（`__EVENTTARGET` 指定触发控件 + `__VIEWSTATE`）。
3. **剩余电量**在查询页 HTML 里，形如 `7#201剩余电量：XXX.XX 度`。
4. **购电/用电记录**是两个独立页 `buyRecord.aspx` / `usedRecord.aspx`，`?p=<页码>` 分页。
5. **照明/空调两套表计**：楼栋下拉里 `01~09` 是公寓照明、`21~28` 是空调，各自独立查。

## 2. 入口与会话

```
GET https://sdcx.hpu.edu.cn/Default.aspx   → 查询页（含 __VIEWSTATE）
```
- 无需登录、无鉴权头。
- 响应 HTML 里 3 个 `<select>`：`drlouming`（楼栋）、`drceng`（楼层）、`drfangjian`（房间）。
- 每次回发都要带**上一次响应里的 `__VIEWSTATE`** 和 `__VIEWSTATEGENERATOR=CA0B0334`（WebForms 状态）。

---

## 3. 三级联动接口（POST /Default.aspx）

统一 `Content-Type: application/x-www-form-urlencoded`。关键字段：

| 字段 | 含义 |
|---|---|
| `__EVENTTARGET` | 触发回发的控件 id：`drlouming`/`drceng`；点查询按钮时为空 |
| `__EVENTARGUMENT` | 空 |
| `__LASTFOCUS` | 空 |
| `__VIEWSTATE` | 上页返回的隐藏字段（必带，Base64） |
| `__VIEWSTATEGENERATOR` | 固定 `CA0B0334` |
| `drlouming` | 楼栋 id（见 §4） |
| `drceng` | 楼层 id（见 §4） |
| `drfangjian` | 房间 id（见 §4） |
| `radio` | `usedR`=用电记录 / `buyR`=购电记录（点记录按钮时） |
| `ImageButton1.x` / `.y` | 图片按钮点击坐标（任意值，如 63/18） |

**联动流程**：
1. 选楼栋：`__EVENTTARGET=drlouming`, `drlouming=07`, 其余空 → 响应里楼层下拉更新。
2. 选楼层：`__EVENTTARGET=drceng`, `drlouming=07`, `drceng=0702` → 响应里房间下拉更新。
3. 选房间 + 点查询：`__EVENTTARGET=''`, `drlouming=07`, `drceng=0702`, `drfangjian=070201`, `ImageButton1.x/y` → 响应里出现剩余电量。

## 4. 楼栋 / 楼层 / 房间字典（已从 HAR 提取）

### 4.1 楼栋 `drlouming`（18 项）
照明表计：`01`=1号公寓照明 … `08`=8号公寓照明，`09`=商铺表。
空调表计：`21`=1号楼空调 … `28`=8号楼空调。

### 4.2 楼层 `drceng`（随楼栋联动，7号楼样本）
`0701`=1层, `0702`=2层, `0703`=3层 … `0707`=7层。

### 4.3 房间 `drfangjian`（随楼层联动，7号楼2层样本，共 36 项）
编号规则：**`楼栋(2位) + 楼层(2位) + 房间序号(2位)`**，如 `07`+`02`+`01`=`070201`=7#201。
样本：`070201`=7#201, `070202`=7#202 … `070210`=7#210淋浴间 … `070239`=7#239（缺 070209/211/230/232 等，说明该校实际房间号跳号）。

> ⚠️ **"寝室不全"的原因**：页面只返回**当前选中楼栋+楼层**的房间，不是全量字典。
> 要生成完整 `hpu_rooms.json`，需遍历每栋楼×每层各联动一次。本次只抓到 7 号楼 2 层。
> 实现策略建议：**不预先内置全量房间表**，改为在 App 内做三级联动（复刻 §3 的回发），
> 让用户现选；房间列表动态从服务端拿，天然不会缺。

## 5. 剩余电量（查询页）

选中房间查询后，`Default.aspx` 响应 HTML 含文本：

```
7#201剩余电量：XXX.XX 度
```

- 房间名与电量在同一文本节点，正则可提：`(\S+)剩余电量：([\d.]+)\s*度`。
- 数值单位：度（kWh）。电价见记录页 `单价(元/度)`。

## 6. 购电 / 用电记录页

在 `Default.aspx` 选好房间后，带 `radio=buyR|usedR` 点查询 → 302 → 跳转：

| 记录 | 跳转 | 表格列 |
|---|---|---|
| 购电记录 | `GET /buyRecord.aspx?p=0` | 日期 / 房间名称 / 充值电量(度) / 充值金额(元) / 充值人 |
| 用电记录 | `GET /usedRecord.aspx?p=0` | 日期 / 房间名称 / 用量(度) / 单价(元/度) |

- 分页：查询串 `?p=<页码>`（如 `buyRecord.aspx?p=0`）。
- 两个页面同样在顶部显示 `X#Y剩余电量：Z 度`。
- 本次抓包记录表格只有表头（该房间暂无记录或数据行未触发），字段结构已定。

## 7. 与 App 的对接方案（建议）

- **不做全量房间表**：按 §3 在 App 内实现三级联动 WebView 或纯 HTTP 回发，房间动态获取，
  解决"寝室不全"问题；`hpu_rooms.json` 只需存楼栋/楼层骨架（§4.1/4.2），房间层动态拿。
- **无需登录改造**：电费模块独立，不接 `HpuSessionStore`。
- **解析器**：参照 `HpuScheduleParser` 写 HTML 解析（剩余电量、记录表格都是固定 HTML 结构）。
- **客户端**：参照 `HpuEamsClient`，用 `HttpClients.hpu()` 或新建一个不注入会话的 OkHttp（本站点无需 cookie）。
- **数据落库/展示**：电量页 + 4×2 组件，沿用现有郑大电量页 UI（切换数据源）。

## 9. App 端实现现状（0.3.0-hpu）

- **入口**：今天页「宿舍用电」卡常驻 + 校园服务页入口 → `ui/electricity/ElectricityScreen`。
- **三级联动**：楼栋（照明+空调**合并成一条物理楼**）→ 楼层 → 房间，三列网格 + 不自动聚焦的搜索框；
  选完房间一次查询照明与空调两套表计（`queryRoom` 内部按编号换前缀，各走一遍 楼栋→楼层 回发）。
- **记忆**：`ElectricityPrefsStore` 存 `campus_key/base/floor_id/room_id` 与读数快照
  （`read_location` 记录这批读数的房间，避免"改楼栋未查询"时首页数字与房间名错位）。
- **编码**：`Default.aspx` GB2312 / `usedRecord.aspx` UTF-8，客户端逐响应嗅探解码。
- **负数电量**：欠费房间返回 `剩余电量：-X.XX 度`，正则必须写 `-?[\d.]+`（写 `[\d.]+` 会整条漏解析，
  表现为"这个房间查不到"）。UI 照实显示负值并标「欠费」。
- **缴费/明细**：不在 App 内实现，跳微信公众号「河南理工大学微后勤」（复制公众号名 + 拉起微信，
  系统无公开接口能直达某个公众号主页）。
