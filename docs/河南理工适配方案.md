### 关键判断（2026-11-19 真机实测后更新）

6. 电费有**独立查询网页**（南 `183.169.255.4:8080`、北 `sdcx.hpu.edu.cn`），电脑 F12 可抓，

   相关 UI 入口也已隐藏。

### P1 / P2 UI 接通（2026-11-19）

已把协议层接进 App 主链路，所有分支由 `SchoolConfig.isHpu` 控制（郑大版逻辑完整保留）：
- 登录：`AppNav` 的 ROUTE_LOGIN 在 HPU 版显示 `HpuLoginScreen`（WebView 打开 UIA 登录页，
  用户手输验证码）；跳回教务域名后从 CookieManager 收集 `*.hpu.edu.cn` Cookie，
  `HpuSessionStore.adoptFromWebView()` 校验 `CASTGC` 并加密持久化，启动时 `restore()` 灌回。
- 登录态：`ScheduleViewModel.currentLoggedIn()` HPU 版看会话 Cookie（郑大看 CAS 令牌）。
- 课表：`HpuScheduleRepository.sync()`（会话校验 → 学期页 → 课表 → 按周展开落库，source="hpu"），
  由 `syncRemote()`/`syncCourseTable()` 按学校分支调用；`loadSemester` 的所有同步点已切分支。
- 数据共用：HPU 与郑大落同一套 Room 表，课表网格/首页时间轴/桌面组件/课程总览自动复用。
- 桌面组件节次时间经 `periodProvider` 取 HPU 双作息，不联网。
- ⚠️ 未真机验证（本机无 JDK）：需用户在 Android Studio `./gradlew test` + 真机登录抓包确认。

## 4. 风险与取舍

- **法律/合规**：项目是非官方作品；校名、校徽属学校无形资产（章程第八十六条：未经授权不得营利性使用）。发布前需确认用途与授权边界。
- **接口时效**：高校接口变动频繁，原项目的郑大接口在 2026 年也多次调整。任何阶段的实现都要带"接口失效 → 明确提示 + 本地快照兜底"，不要静默失败。
- **明文 HTTP**：旧 HPU 教务接口走 HTTP，账号密码 Base64 并非加密；P1/P2 实现时必须在校园网抓包确认是否有 HTTPS 入口，避免把凭据暴露在明文链路。
- **密码存储**：原项目坚持"不存密码"，仅因郑大网关认证破例存加密密码。HPU 若必须用密码换 token，需要单独做安全设计（加密存储 + 明确告知用户），不能默认照搬。
- **测试环境**：本机有 JDK 17 + Gradle 8.9，但**无 Android SDK / Android Studio**，无法编译 APK；
  P0 之后的所有 Kotlin 改动只做了静态校验（括号/import/资源引用/关键 API），
  需要你在 Android Studio 里跑 `./gradlew test` 与真机登录验证。若真机试运行失败，用下面的日志导出回传分析。

## 4.5 试运行与日志导出（2026-11-19）

真机试运行若闪退或异常，**不用连电脑看 logcat**：

1. 重新打开 App（崩溃后已被系统杀掉），进「更多 → 账号 → 登录状态」（诊断页）。
2. 顶部「运行日志」卡片会显示"⚠️ 检测到上次崩溃"及堆栈摘要。
3. 点「**导出日志（分享给开发者）**」→ 选微信/邮件把 txt 发回即可分析。

实现位置：`core/CrashLog.kt`（全局 `UncaughtExceptionHandler` + 关键事件，写入 `filesDir/crash/`），
在 `ZZUPocketApp.onCreate` 最早安装；日志自动打码令牌/手机号，仅在用户主动点分享时导出。
FileProvider 已在 Manifest 注册（`${applicationId}.fileprovider` + `res/xml/file_paths.xml`）。

> 未适配模块（图书馆 / 校园卡）**当前没有任何入口**：「更多 → 校园服务」只列出了
> 宿舍用电与空闲教室两项，不存在"点进去是空壳/待接入"的页面。
> 代码里也**没有**按 Integration 状态显示或隐藏入口的机制（早期方案提过，未落地）——
> 新增模块的落点是：`CampusScreen` 加 `Entry` → `AppNav` 注册路由 → 对应 Screen。
