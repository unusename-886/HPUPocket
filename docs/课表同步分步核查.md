# 课表同步分步核查（HPU EAMS）

> 触发：2026-11-19 18:38 runtime.log —— 登录完全成功，但 `courseTableForStd.action` 只拿到 `len=59` 空壳，
> 重试即弹回 `loginExt.action`，课表同步 100% 失败。

## 0. 现象拆解（日志已给的事实）

| 日志行 | 说明 |
| --- | --- |
| `nav: ... homeExt.action` / `adopt OK -> done` | CAS 兑票链全通，登录落地页正确 |
| `cookie synced to WebView: zhjw=3 uia=2 webvpn=1 shared=2` | 会话按域写回 CookieManager 成功 |
| `probe login.action: code=200 finalUrl=...homeExt bodyLen=23784` | **OkHttp 通道**拿到完整首页，持久化 Cookie 有效 |
| `isValid(local)=true` | 本地会话标志齐全 |
| `webview attempt 1 -> courseTableForStd.action` | WebView 通道开始抓学期页 |
| `onPageFinished: courseTableForStd.action`（**未跳转**）| 页面确实停在目标 URL，没被 302 |
| `attempt 1 not ready (lastLen=59)`，持续 9s | **主文档只有 59 字符**，不是登录页，也不是真实内容 |
| `attempt 2/3 bounced to loginExt.action (lastLen=0)` | 会话在两次尝试之间彻底失效 |

**关键矛盾**：同一时刻，OkHttp 说会话有效（23784 字节首页），WebView 说会话无效（59 字符空壳→弹回）。
两个通道结论相反，只有两种解释：
1. WebView 没带上会话（Cookie 域/Path/属性写坏了）；
2. **抓取前那次 OkHttp 探测本身把会话换掉了**（已登录状态下再走一遍 `login.action` 会重新 CAS 兑票、签发新 EAMS 会话，WebView 手里的旧 `JSESSIONID` 随即作废）。

## 1. 六步核查（每步独立可判定）

| 步骤 | 检查什么 | 判定标准 | 日志标志 |
| --- | --- | --- | --- |
| S1 | WebView 这次请求**带了哪些 Cookie** | zhjw 域应含 `JSESSIONID / GSESSIONID / srv_id / HuauAuthName`；缺失或值是旧的 ⇒ Cookie 写回有问题 | `fetch#N ctx: url=... cookies=n[...]` |
| S2 | **WebView 侧**会话是否成立 | 加载 `homeExt.action` 仍停在 `/eams/` ⇒ 成立；跳 `loginExt.action`/webvpn ⇒ 明确失效 | `warmup: session ALIVE ...` / `session DEAD -> ...` |
| S3 | 学期页是不是真空壳 | `readyState=complete` + `title` 空 + `body.innerHTML=0` ⇒ 服务端回了空文档（未授权 JSP 提前 return）；有 body 但无 `semesterCalendar` ⇒ 结构变了 | `fetch#N tiny body(59) snap=... raw=<全文>` |
| S4 | 主框架 HTTP 状态与重定向 | 出现 302/401/403 或 `onReceivedHttpError` ⇒ 网关拦截，不是解析问题 | `webview main frame http <code>` |
| S5 | 课表 POST 是否返回 `TaskActivity` | 页面内 `fetch` 拿到含 `TaskActivity` 的 HTML ⇒ 数据到手；`done but no TaskActivity` ⇒ 参数/ids 不对 | `page-fetch: got course table len=...` |
| S6 | 解析与落库 | `parsed>0` 且 `persisted OK` | `fetchCourseTable: bodyLen=... parsed=...` |

**空壳全文一定要打出来**：59 字符的页面没有秘密，整段打进日志就能立刻分辨
「空白错误页 / iframe 壳 / 被网关拦 / 未授权 JSP 空返回」四种情况，不用再猜。

## 2. 本轮已落地的改动

1. **S1/S3/S4 诊断**（`HpuEamsWebFetcher`）
   - 每次抓取前打 `ctx`：URL + CookieManager 里该域实际的 Cookie 名单；
   - `onPageStarted` / `onReceivedHttpError` 记录主框架状态；
   - 正文 ≤300 字符时打 `tiny body` 全文 + `readyState|title|body长度` 快照（每次尝试只打一次）。
2. **S2 会话自检**（`HpuEamsWebFetcher.warmUp()` + `HpuEamsClient.fetchSemesterPage()`）
   - 抓学期页前先加载 `homeExt.action`；明确被弹回 ⇒ 直接放弃，不再把 3 次 ×9s 烧在注定失败的通道上；
   - 超时（无法判定）不当失效，继续正常抓取。
3. **解除探测抢会话**（`HpuSessionStore.isValid()`）
   - 同步路径改为**纯本地判定**，不再向学校发任何请求；
   - 原网络探测迁到 `probeNetwork()`，只在诊断页「检查会话」里手动触发。
4. **Cookie 写回改为「缺失或值不同才写」**（`syncToWebView()`）
   - 登录成功后 CookieManager 里本来就有最新一份，重复 `setCookie(...; Path=/)` 会把 Path 从服务端原值改成 `/`，
     产生同名双份 Cookie，服务端取哪一份不确定；现在同值直接跳过，日志多打 `written/kept`。
